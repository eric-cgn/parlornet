# Frontends

A frontend is the program a player uses to reach a parlor. It can be an old game program that speaks its original protocol, which these docs call a native client. It can be a web browser or a telnet program, which work on any computer. It can also be a program written for ParlorNet's own protocol. Each frontend speaks one protocol. On the server, a server extension speaks that protocol back and passes the player's moves on to the core.

ParlorNet is mainly for native clients, the game programs first released about 25 to 50 years ago. Browsers and telnet programs are the fallback for any computer, old or new, so that rule does not apply to them. The [retro window](clients.md#the-retro-window) part of clients.md has the policy.

The docs site's [Clients page](http://docs.parlornet.org/) lists the frontends game by game. Each game has a table of its native clients, with the year, the systems each one runs on, its protocol's key and a link to its own page. The browsers and telnet programs play every game, so they are listed once at the bottom of the page. A finder narrows the lists by platform and processor. Each program's own page has its history, setup, known quirks and screenshots, as on the page for [Reversi The Eclipse](http://docs.parlornet.org/clients/eclipse.html). The [Browsers page](http://docs.parlornet.org/browsers.html) says what every browser needs, and the [Telnet programs page](http://docs.parlornet.org/telnet.html) says what every telnet program needs. The site builds these pages from `adapters/clients.py` and the pages in [clients/](clients/README.md).

- [design.md](design.md) says how a frontend should look and work. It gives the design principles, such as `/` for the command line, the program flow from connecting to signing out, and the names, sentences and keys every frontend shares.
- [protocols.md](protocols.md) describes the protocols and their server extensions, how to connect and sign in with each, and their history. The web site is under [HTTP and HTML 3.2](protocols.md#web-site), telnet is under [telnet](protocols.md#telnet), and a program of your own speaks the [native protocol](protocols.md#native-protocol).
- [clients.md](clients.md) says where each program comes from, with its license and the evidence that it meets the site's needs. It also lists the games that no native client reaches yet.
- The Games section of the web site's [welcome page](http://parlornet.org/welcome.htm#games) lists each game, and each game's own page has the rules played here.
