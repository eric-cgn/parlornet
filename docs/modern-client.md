# ParlorNet Play: the modern client

ParlorNet Play is the game server's client for today's browsers, phones and tablets, at `/play/`. It is a server extension of its own, the Play extension (`adapters/playserver.py`), on port 6513, normally behind a reverse proxy that serves it over HTTPS (Serving it over HTTPS, below). It plays at the same tables as every other way in: the HTML 3.2 pages, telnet and the period game programs. The operator turns it on or off like any other extension, and it runs with or without the web extension. While it runs, the welcome page links to it and the web site's `/play` sends browsers to it.

It is one web app: a shell that does everything common to all games, and a module for each game that draws its board and turns clicks and keys into moves. Backgammon, Reversi, Grid Words, Cannon Fire and Rummy Tile Classic have modules. The other games are marked unfinished where a game is chosen to start a table, and their tables open with a plain view (the view lines, the legal moves as buttons, a box for a typed move) and a link to the classic page, so every table can be reached.

## Using it

- **The message of the day.** The parlor's message of the day (`MOTD`, the same text every way in shows) opens in a window when it has changed since this browser last closed it; the cookie `pnmotd` (`Path=/play/`) holds a hash of the text it showed. The speech-bubble button at the top right shows it again at any time.
- **Signing in.** Sign in or make a new account on the first page. The server asks its questions one at a time (a password, an email address, the password the server emailed, a new password of your own, a yes or no), exactly as on every other way in; the page shows each one. After signing in, the browser keeps Play's own session cookie, so a reload, or a phone waking up, carries on without signing in again. With Stay signed in checked on the sign-in form, Play also keeps a sign-in key in a cookie of its own, so the browser signs in again without the password after its session ends (docs/accounts.md, Staying signed in). The classic pages are another site (plain HTTP on port 6500) and keep their own session, so signing in on one does not sign you in on the other. Sign out ends Play's session and forgets the key.
- **The lobby** lists the tables (yours first, then those you can join, with the bot's open tables after those where a person waits, then those you can watch), your invitations and who is online, and has a form to start a table with the game, its rules and players where it has a choice, the time per turn, private or public, and Play the bot. The bot sits down a few seconds after it is invited. Under a table's players, a smaller line says what each one plays with, where the server says it, such as "ann with GameMaster 1.0.0 + ParlorNet 0.5 on a Macintosh Plus" (`LST clients`). Games without a board in Play carry an unfinished tag in that form.
- **A table.** The board fills the window. Beside it (below it on a phone held upright) are the players with their scores, what each plays with in a smaller line where the server says it (`VUE table C`), and the clock of the player to move, the game's own panel, an invitation box while the table waits for players (with Invite the bot), table talk, and Lobby, Stand up or Stop watching, and Resign. Leaving the page never resigns; the seat waits and the turn clock runs.
- **Who sat down with what.** When a player sits down, the table talk says what they play with on the same line, such as "ann sits down with GameMaster 1.0.0 + ParlorNet 0.5 on a Macintosh Plus" (the `CLIENT` event that follows `JOIN`). A player who comes back to a game from another program gets a line of their own, such as "ann now plays with ParlorNet Play in Firefox 132 on macOS". Where the program named nothing, the line says only that the player sat down. At a private table only its creator and the players seated there see what the others play with.
- **With what each turn was played.** The table talk lists the moves as they come. Under a move's line, a smaller line says which program and machine the player used, such as "with ParlorNet for the Apple IIe 1.1 on an Apple IIe (enhanced)". Play reads the table's turns (`TRN table n`) when the table opens and after new events arrive, at most every three seconds, and puts each turn's line under the first move line of that turn, the one that names its player when there is one. A turn whose player's program named neither gets no line. At a private table the programs and machines go only to the players seated there, so others see the moves without them.
- **Profiles.** A player's name opens their profile wherever Play shows it: in the lobby's tables, invitations and Online now, on the seats at a table, in the table talk and the notes, and in the activity. The profile opens in a window over the page, so a table stays open beneath it. It shows the machine the player prefers, if they named one, the games they played to the end at public tables (with the games' names from the server's list), the programs and the machines they played their turns with at public tables, each with its count, and their latest public turns. On your own profile a box sets your preferred machine, up to 40 characters, which the server cleans before keeping (`PFL SET PREF`); saving it empty clears it. The address `#/player/NAME` opens a profile over the lobby. A profile holds only what the player wrote and what the server counted from play: no address and nothing from a private table.
- **Activity** is the pulse button at the top right (and All activity under Recent turns in the lobby). It lists the latest 30 turns at public tables, newest first, each as a sentence such as "eric played FRAULEIN for 65 in Grid Words with BobGrid 2.3 on a Sun SPARCstation", with how long ago and a link to the table. A turn the game does not put in words reads "eric played a turn in Grid Words", and the program or the machine is left out when the player's program did not name it. The words follow the classic pages and telnet: "the" goes before a few period products (the Outland Gateway, the ParlorNet bot), a system such as macOS or Windows takes no article, and any other machine takes "a" or "an". The page asks for the turns (`FEED 30`) when it opens and every 45 seconds while it is visible, and again when the browser tab comes back after that long; the lobby shows the latest five in the same way. A server whose core does not keep turns answers with an error, and the page then says so in place of the list.
- **The leaderboard** (`#/scores`, and Full leaderboard under Leaderboard in the lobby, which shows the first five) lists up to 50 players with their rank, points, wins, draws, losses and resignations, in every game or in the one chosen, each name opening the profile (`TOP`). Both say that any score is easy to get on a public server, since the leaderboard is meant for conferences, festivals and LAN parties. A profile shows the player's score and rank (`PFL SCORE`). On a server whose operator turned the leaderboard off, neither shows.
- **Full screen** is the button at the top right, or F on the board; Escape leaves it. In a browser without the Fullscreen API the page fills the window instead. The board is drawn at the screen's own resolution at every size, from a phone to 4K and ultrawide screens; on wide screens the panels sit in two columns beside the board.
- **Settings** has sounds on or off, less motion (also taken from the system's reduced-motion setting), 3D drawing (WebGL) or flat drawing (2D canvas), notifications, the side of the Backgammon home board, the Grid Words colors and the Rummy Tile colors. The first three are kept in this browser; the home board's side (`PRF` key `bghome`, `right` or `left`) and the colors are kept with the account, and so is the choice of notifications, which are turned on in each browser.
- **Notifications.** Where the parlor offers them, Play can send a notification when it's your turn, when a game you are in ends and when someone sits down at your waiting table, with Play closed. [play-notifications.md](play-notifications.md) says how to turn them on in each browser, what they say and how they work; Play links its own copy of those instructions from Settings.

## The games

**Backgammon.** A wooden board with felt; your home board is at the bottom right, whichever seat you have. Drag a checker to where it goes, or click it and then the place; a checker with only one way to go moves on a single click. The legal steps are also listed as buttons. The dice tumble when they are rolled; dice already played are grayed. Roll and Double, Take and Drop, Undo step and Confirm move are in the panel (R rolls, U undoes, Enter confirms). The doubling cube sits on the bar, and moves to its owner's side. Offers to resign are under Offer to resign; an offer to you is answered in the panel. On the keyboard, the arrow keys pick a checker that can move, Enter selects it, the arrows pick where it goes and Enter moves it. With the home board on the left (Settings), the board is drawn mirrored, points 1 to 6 at the bottom left and the tray on the left; the moves are the same.

**Reversi.** Discs drop onto the felt and the captured ones turn over one after another, outward from the disc placed. Your legal squares are marked on your turn: click one, or use the arrow keys and Enter on the board, or the list in the panel. The last move is framed.

**Grid Words.** The board is drawn in your colors, with a legend in the panel. Drag tiles from your rack to the board, or click a tile and then a square, or click a square and type: the letters come off your rack and the cursor moves on across or down (Space turns it; Backspace takes the last tile back; Escape recalls them all; Enter plays). A blank asks which letter it stands for. As tiles are laid, the server scores them (CHK) and the panel shows the points and words, or why the play would be refused; this works while waiting for your turn too. Recall, Shuffle, Exchange (click the tiles to put back) and Pass are in the panel, and Type a play takes a play written out (`h8 a WORD`).

**Cannon Fire.** The landscape is drawn side-on, with the tanks on it in their seats' colors, each with its hit points, and the wind at the top left. On your turn, set the angle and the power with the arrow keys on the board (Shift for steps of 5), by dragging from your tank (the direction is the angle and the length the power), or with the sliders and boxes in the panel, and fire with Space, Enter or Fire. Before the shot you may drive left or right (A or `[`, D or `]`, or the panel's buttons), as far as the distance slider says; the panel says where each way would end. Shells fly along the path the server sends and burst where it says; the crater, the damage and the tanks that fall come after the burst, from the server's events.

**Rummy Tile Classic.** Each set on the table lies on a mat, with no words or marks over it. A set that is not valid yet lies on a red mat with a red edge, a set made or changed this turn has a thin light edge, and the sets you may not touch before your first meld have dimmed tiles. Above the table are the pool and each player's rack count, with ✓ for a player who has made the first meld and ▶ for the player to move; your rack lies in a flat tray below, sorted by color or by number (the buttons over the tray, O on the board; kept in this browser). Click tiles on your rack to pick them, then a set or the new set; or drag them there, or onto a free part of the table to start a new set in that place. Click a tile on the table, then another set, the new set or your rack (only a tile you played this turn goes back); with a tile picked after the first of its set, the split mark under it splits the set before it. Click a set by its mat (the space around its tiles), then another set, to join them. The line over the buttons says how the turn stands, with the first-meld points while you stage it (`first meld 24 / 30`). Undo takes back the last step, Reset starts the turn over and Done ends it. When Done would not count the turn, the first press only says why and a second press takes the turn back and draws a tile; with nothing played the button is Draw (Pass when the pool is empty). The panel has the same actions as buttons, with a set chosen from a list (the set chosen is lit on the board), the tiles as buttons, a box for a step written as the protocol writes it (`R7B7K7-n`, `3.2-5`, `3/4`), the rules in short, and at the end each player's score and tiles left; the board shows the result too. On the keyboard, the arrow keys move a frame over the sets, the tiles, the new set and the buttons, Enter or Space picks or places, N makes a new set, S splits, R takes a tile back, U undoes, D is Done and Escape puts everything down. Two to four players.

The layout of the table is each player's own. Drag a set by its mat to put it anywhere on the table; it snaps to a grid of half a tile across and a row down, and a set let go over another moves to the nearest free place, so sets never overlap. The server keeps only the sets' order, so the places are kept in the browser for each table (`localStorage`, by the server's address and the table's number, for the last 40 tables) and come back after a reload. A new set goes where you made it (the new set's place, or where you dropped its tiles), or for other players' sets into the first free place; the second part of a split set goes beside the first, and a tile moved to a new set beside the set it came from. A set the server changes keeps its place; when it grows into a neighbor, the neighbor steps aside along its row. A set that goes frees its place. On the keyboard, Shift and the arrow keys move the set under the frame, or the picked set, a tile or a row at a time, past any set in the way; with a set picked, the panel has buttons for the same moves.

The board zooms and pans. By default it shows the whole table, all the sets and your rack, but never smaller than the size at which the board would show the sets in rows in table order; that size is the smallest zoom. When the sets are spread wider than that, the default view starts at the left edge with your rack and the buttons in view, a small arrowhead at the edge of the view points towards each set out of sight, and you pan to see the rest. Zoom with the − and + buttons in the board's top right corner, with Ctrl or ⌘ and the scroll wheel (or a trackpad pinch), with two fingers on a touch screen, or with the + and − keys. Drag the free table (with the mouse or one finger) or scroll to pan, and while you drag a set or tiles near the edge of a zoomed board, the view follows. Fit, or the 0 key, goes back to the default.

## Grid Words colors

The default palette and the presets are described, with the reasons for them, in [design/gridwords-colours.md](design/gridwords-colours.md). In Settings choose a preset (Slate, Daylight, High contrast, Grayscale) or set a color for each of the board, the four kinds of premium square, the tiles and the letters; the preview shows them. The choice is kept with your account (`PRF` key `gwcolors`, in the namespace Play shares with the classic pages), so their Grid Words colors page shows and changes the same choice. Telnet keeps its own (the `colours` command on a Grid Words table).

## Rummy Tile colors

The tiles are ParlorNet's own design, described with the palette and the reasons for it in [design/rummytile-colours.md](design/rummytile-colours.md): flat tiles with the number drawn in its color, and a star on the joker. Color tells the tiles' families apart, so the Color-blind safe and High contrast presets are there for players who need them. In Settings choose a preset (Slate, Color-blind safe, High contrast) or set a color for each of the table, the tiles, the joker's star and the four colors; the preview shows four tiles and a joker. The choice is kept with your account (`PRF` key `rtcolors`); the classic pages and telnet draw the game in their own way.

## Accessibility

- Every control is a real button, link or form field, reachable with the keyboard, with a visible focus ring.
- The board is a focusable element with a text label that says the game's state; moves made by anyone are announced in a polite live region, and so is your turn.
- Each game can be played from the keyboard, and each also offers its moves as buttons in the panel.
- Color is not the only sign, with one exception. Grid Words premium squares carry their names and word squares a frame, a Rummy Tile Classic set that is not valid lies on a filled mat with an edge (a set changed this turn has only a thin edge, the others neither), the line over the buttons says how the turn stands, and the panel and screen readers name each set's kind, and the player to move is named in words. The exception is a Rummy Tile Classic tile's color on the board, which is shown by the color of its number alone; the Color-blind safe and High contrast presets are there for players who need them, the panel's Tiles as buttons shows each tile with its letter (`R7`), and screen readers name each tile in words.
- Text meets WCAG contrast on the dark theme; the layout follows the browser's text size.

## How it is built

The files are in `adapters/play/` and the Play extension serves them as they are, except that `index.html` gets the classic pages' full address (the Host's name and the port the web extension declared), or none while the web extension is off, and then the page hides its links to them: `index.html`, `play.css`, `net.js` (the PARLORNET/1 client over the WebSocket), `gfx.js` (the renderer), `app.js` (the shell), `game-<type>.js` (the game modules), `/play/palette.json` and `/play/rummytile-colours.json` (the Grid Words and Rummy Tile presets, from `adapters/palette.py` and `adapters/rtpalette.py`), `sw.js` (the service worker for notifications), `manifest.webmanifest` and the icons (`icon-180.png`, `icon-192.png` and `icon-512.png` are drawn by tools/play_icons.py), and `notifications.html`. Nothing third-party is used or loaded, whether libraries, fonts or anything from another site, and the pages' Content-Security-Policy tells the browser so.

**Transport.** The page opens a WebSocket to `/play/ws` and speaks PARLORNET/1 over it, one line per text message. The server side is the Play extension, which relays each line to the core on its extension channel; every rule, the sign-in included, stays in the core. docs/protocol.md (WebSocket) has the details. On a page loaded over HTTPS the client uses `wss://` instead of `ws://`.

**Serving it over HTTPS.** The Play extension speaks plain HTTP. A reverse proxy on the host terminates TLS, with a certificate from Let's Encrypt for example, and passes `/play/` to port 6513 with the WebSocket upgrade headers; deploy/README.md has an example. Two settings tell the extension about it. `play.public_url` (`PARLOR_PLAY_URL`) is the address players open, such as `https://parlornet.org/play/`: the WebSocket then accepts that origin only, the cookie is marked `Secure`, the port declared to the core is that URL's, and the web extension's `/play` answers with a 301 to it. `play.proxies` (`PARLOR_PLAY_PROXIES`) lists the proxies' addresses: from those, and only those, the extension takes the browser's address from `X-Forwarded-For` (for the core's per-address limits) and its scheme from `X-Forwarded-Proto`. The extension never sends HSTS, which would reach the classic pages' port on the same name and turn modern browsers away from them.

**What Play says it is.** On every new WebSocket, reconnections included, Play tells the core which browser and system it runs in, right after the greeting and before signing in: `CLI PROG ParlorNet Play in Firefox 132` and `CLI MACH macOS`, for example (docs/protocol.md, Clients and machines). The browser is Firefox, Safari, Chrome, Edge, Opera, Samsung Internet, Vivaldi, Brave or Chromium with its major version, and the system is macOS, Windows, iPhone, iPad, Android, Linux or ChromeOS. The page works these out itself in `net.js`, from `navigator.userAgentData` where the browser offers it and otherwise from the User-Agent string; an iPad that presents itself as a Mac is told apart by its touch screen. A browser it does not recognize is sent as plain `ParlorNet Play`, and an unknown system is not sent at all. Each text is at most 40 characters. The claim only labels the turns played on that connection, and Play does not wait for the answer, so a core without `CLI` changes nothing.

**Polling.** At a table the client asks for new events (`SIN`) every second while the page is visible, and for the view (`VUE`) when something happened; the lobby asks every four seconds. A move's reply carries its events at once.

**Drawing.** `gfx.js` draws a scene, a list of items in board units (a painted board, rounded boxes, discs and checkers, lettered tiles, dice, flat marks and labels, soft shadows, and a landscape made from a row of heights), with hand-written WebGL: one shader with a key light, a sky light and highlights, meshes made in code (a tile may carry a face its game paints), and textures painted on 2D canvases at the board's size on the screen (so text stays sharp). The same scene is drawn from straight above with the 2D canvas when WebGL is missing or the player chooses flat drawing.

### A game module

A module registers itself with the shell:

```js
PN.register("reversi/1", {name: "Reversi", create: function (api) { return game; }});
```

`create` gets the shell's API and returns the game. The API has `tid`, `key`; `seat()`, `names()`, `name(seat)`; `mov(tokens)` (sends `MOV`, applies the reply's events and the next view, and resolves with the final line), `chk(tokens)`, `und()`, `end()`, `req(line)`; `myTurn()`, `over()`, `common()` (the view's common lines: status, scores, clock, bots, whose turn); `palette()` and `rtPalette()` (the Grid Words and the Rummy Tile colors, worked out); `redraw()`, `sound(name)`, `announce(text)`, `toast(text)`, `askLetter()`, `motion()`; and `panel`, the element for the game's own controls, with `el` and `clear` to build it.

The game returns these (all but `view` and `frame` may be left out):

| Member | What it does |
|---|---|
| `view(lines, common)` | A new view: the `VUE` lines (with `G` the first time the game is under way). |
| `event(text, quiet, seq)` | An event, the text after `EVT table seq`, and its number. `quiet` for the table's history when it opens: no animation. |
| `describe(text)` | The event as a line for the table talk, or null. |
| `frame(now)` | The scene: `{view: {w, h, tilt, pad, z, win, aspect}, items: [...], bg}`. `win` (optional) is the part of the board to show, `{x, y, w, h}` in board units, for a board that zooms; `aspect` (optional) is the width over the height the stage takes on a narrow screen, when it is not the board's own. |
| `animating()` | True while something moves: the shell keeps drawing. |
| `pointer(kind, p, event)` | `down`, `move`, `up`, `leave`, `cancel` at `p`, a point on the board in board units; `p.at(z)` is the point under the pointer at height `z`. Each finger is its own pointer (`event.pointerId`). |
| `wheel(p, event)` | The wheel over the board; true if used (the page then does not scroll). |
| `key(event)` | A key on the focused board; true if used. |
| `status()` | A sentence for the board's text label and the live region. |
| `seatColour(seat)` | The seat's color, for the players list. |
| `paletteChanged()`, `destroy()` | The colors changed; the table is closing. |

Adding a game means adding `game-<type>.js` with its module and a `<script>` line in `index.html`.
